## 0. Коротко о том, что за приложение и как устроено

- **Стек:** Python 3.12 + PyQt5, pyvista/pyvistaqt (3D-превью), matplotlib, gmsh (сетка), numpy/scipy, SU2_CFD (решатель), mpiexec (MPI).
- **Точка входа:** `su2_gui.py` → `ui/main_window.py` (`MainWindow`). Дубль-вход `main.py` — просто прокси на тот же `main()`.
- **Модули:**
  - `config/` — настройки + полётные условия (ISA, пресеты самолётов)
  - `geometry/` — параметрические генераторы (фюзеляж, крыло, закрылки, предкрылки, ГО/ВО), «лечение» STL, **Direct CAD Import**
  - `mesh/` — объёмная тетра-сетка через gmsh + запись `mesh.su2` с маркерами (в т.ч. симметрии), **адаптация сетки**
  - `solver/` — сборка `config.cfg`, сессии, фоновые воркеры (в т.ч. **DOE/перебор вариантов**), гибридный CPU+GPU
  - `su2_autoconfig.py`, `su2_config_dialog.py` — устойчивые пресеты + окно настроек SU2 (восстановлены в репозиторий)
  - `optimization/` — правила проектирования (RuleSet), многоточечная оптимизация
  - `physics/` — атмосфера ISA, профили NACA, расчёт сил
  - `ui/` — главное окно (дерево проекта в стиле COMSOL)
- **Состояние кода:** здоровое. `tests/test_backend.py`, `tests/smoke_import.py`, `tests/ast_lint.py` — все зелёные (23 модуля импортируются).

## 2. Детально по приоритетам ТЗ

### Высокий приоритет — Оптимизация формы (требование 5)

**Было:** случайный поиск 6 кандидатов вокруг стартовых параметров.

**Стало (DOE — табличный перебор):**
- На странице оптимизации — группа **«Табличная оптимизация (перебор вариантов)»**:
  - таблица вариантов (Размах / Хорда корня / Хорда конца / Стреловидность);
  - кнопки: «➕ Из текущих параметров», «➕ Ввести вручную…», «🗑 Удалить выбранное», «🧹 Очистить»;
  - кнопка «🔁 ЗАПУСТИТЬ ПЕРЕБОР»: каждая строка = один полный прогон (геометрия перестраивается, сетка перегенерируется, расчёт по выбранным полётным точкам);
  - таблица результатов (вариант → Cl, K, статус) заполняется по мере счёта;
  - по завершении лучший вариант применяется к генератору крыла.
- Бэкенд: `OptimizationWorker` получил параметр `candidates` (список dict-параметров) и сигнал `variant_ready`. Если `candidates` передан — идёт табличный перебор; если нет — прежний случайный поиск (поведение не сломано).
- Правила RuleSet (жёсткие/мягкие) и многоточечность (взлёт/крейсер/посадка) работают в обоих режимах.
- Таблица DOE сохраняется в проекте (`.aop`/JSON).

### Средний приоритет — Аэроупругость (Flutter)

Заказчик выбрал **аналитические оценочные модели в самом приложении** (без
внешних решателей). Реализовано в `physics/aeroelastic.py`:

- **Метод типичного сечения** (2 степени свободы: изгиб `h` + кручение `α`)
  с полной нестационарной аэродинамикой Теодорсена: функция `C(k)` через
  функции Бесселя (и рациональная аппроксимация как запасной путь без
  scipy), циркуляционная и нециркуляционная (присоединённые массы) части.
- **p-k метод**: для каждой скорости решается квадратичная задача на
  собственные значения `λ²(M−B2) − λB1 + (K−B0) = 0`, скорость флатера
  `V_F` — пересечение структурного демпфирования `g` нуля.
- **Дивергенция** — аналитически: `q_D = K_α/(c·C_Lα·e)`, существует только
  при оси упругости за аэродинамическим фокусом (`e > 0`).
- **Оценка параметров сечения по крылу**: консоль с эквивалентным
  лонжероном-коробкой (K_h = 3EI/L³, K_α = GJ/L).
- UI: узел дерева **«Aeroelasticity (Флатер и дивергенция)»** — частоты,
  V_F, V_D, запас, вердикт; кнопка **«📉 V-g диаграмма»** рисует на
  вкладке графиков.

Модель проверена на аналитических пределах (`tests/test_backend.py`):
`C(0)=1`, `C(∞)=0.5`, `|C|<1`, `Im C<0`; стационарные сила и момент
**совпадают с теорией тонкого профиля (Глауэрт) до машинной точности**;
дивергенция совпадает с формулой; при `U→0` частоты равны собственным с
присоединёнными массами и демпфирование нулевое; изолированный изгиб
устойчив на всех скоростях; квазистационарное демпфирование кручения
неотрицательно при любом положении оси упругости; `V_F` растёт с
жёсткостью кручения.

**Границы применимости (важно):** это предварительная оценка для ранней
стадии — 2 степени свободы, несжимаемый поток, оценочные жёсткости. Для
сертификации нужен расчёт по полной КЭ-модели с экспериментальным
подтверждением; это прямо написано в отчёте пользователю.

### Низкий приоритет — Прочность

`physics/structural.py`: нагрузка `n_y·m·g`, три закона распределения
подъёмной силы по размаху (эллиптическое — с аналитическим контролем
`M = 4/(3π)·L·s`, равномерное, треугольное), разгрузка массой крыла,
напряжения в лонжероне-коробке, коэффициент запаса
`MS = (σ_доп/k)/σ − 1` и оценка массы. UI: узел **«Strength (Прочность
корневого сечения)»**.

### Спецфункции и формат конфигурации (пункт 6, постановка от заказчика)

- **Спецфункции** = постобработка: `postprocessing/polar.py` (поляра,
  наклон Clα по линейному участку, α₀, Cd₀ и фактор Освальда из
  `Cd = Cd0 + k·Cl²`, Cl_max и угол сваливания, K_max, скорость
  сваливания `V = √(2W/(ρS·Cl_max))`) и `postprocessing/report.py`
  (3 шаблона: «краткий», «полный», «поляра»; вывод текст/HTML; CSV с
  разделителем «;» и BOM для Excel). Отчёт включает разделы аэроупругости
  и прочности, если они рассчитаны.
- **Формат конфигурации** = `config.cfg` + именованные пресеты:
  `su2_preset_format.py` — JSON-формат `.su2preset` (format/schema_version/
  name/description/based_on/created/params), каталог ключей берётся из
  `su2_config_dialog.PARAMS`, валидация (неизвестный ключ = предупреждение,
  а не ошибка — SU2 развивается), 3 встроенных шаблона, атомарная запись
  (`.tmp` + `os.replace`), diff двух пресетов, генерация строк `KEY= VALUE`.
  UI: узел **«Config Presets (Формат конфигурации)»**.

- **SU2_ADAPT и mpiexec** не запускались по той же причине — проверены
  поиск исполняемых файлов и сборка команд.
- Аэроупругость и прочность — оценочные модели (см. границы применимости
  выше), а не замена сертифицированного расчёта.

## 3. Детально по требованиям 1–4

### 3.1. Вычислительная эффективность и параллелизация (требование 1)

**Было:** слайдеры нагрузки CPU/GPU, `mpiexec -n N`, SU2_PARTITION, гибрид CPU+GPU, INNER_ITER по качеству сетки, RAMP_AOA.

**Добавлено в этой итерации:**
- **Подсказка по числу ядер** при старте расчёта: читается `NPOIN` из mesh.su2 → рекомендация ≈ N/150000 ядер (лог).
- **ETA до конца серии** в `add_result`: среднее время на точку × оставшиеся точки («⏱ Точка 2/5: среднее 95 с/точка, осталось ~5м»).

### 3.2. Плоскость симметрии (требование 2) — уже было реализовано

Полный цикл: UI → `get_symmetry_planes()` → `mesh/gmsh_generator.py` (маркеры) → `solver/config_builder.py` (MARKER_SYM) с защитой от отсутствия маркера в сетке. Осталось прогнать контрольный расчёт и зафиксировать ускорение 1.8–7×.

### 3.3. Адаптивная сетка (требование 3) — реализовано

- `solver/workers.py`:
  - `find_su2_adapt_exe()` — поиск SU2_ADAPT рядом с SU2_CFD.exe / в $SU2_HOME / в PATH;
  - `run_su2_adapt(case_dir, mesh_path, restart_path, adapt_markers, abs_error, log_cb)` — копирует mesh+restart в каталог кейса, пишет `adapt.cfg` (MARKER_ADAPT, ADAPT_ABS_ERROR, ADAPT_BOUNDARY), запускает SU2_ADAPT, возвращает путь к `mesh_adapt.su2`;
  - `_mesh_npoin()` — число точек mesh.su2 (для лога «до/после»).
- `mesh/mesh_worker.py: MeshAdaptWorker` — фоновый поток адаптации (UI не зависает).
- `ui/main_window.py` — кнопка **«🧬 Адаптировать сетку (SU2_ADAPT)»** на странице Mesh:
  1. проверяет наличие mesh.su2 и свежего `restart.dat` (из work/case_*/aoa_*/);
  2. спрашивает подтверждение замены рабочей сетки;
  3. запускает адаптацию, заменяет mesh.su2, показывает «точки до → после».
- Ограничение честно отражено в UI: нужен полный дистрибутив SU2 с модулем SU2_ADAPT (обычно входит в комплект). Если exe не найден — понятное сообщение.

### 3.4. Direct CAD Import (требование 4) — реализовано

- `geometry/generators.py: cad_to_stl(src, out, log)` — конвертация через gmsh (OpenCascade): `gmsh.open` → mesh поверхностей → STL. Поддерживаемые расширения: `.step .stp .iges .igs .x_t .x_b .sat .brep .bdf .nas .ply .obj .off` (`CAD_EXTENSIONS`).
- `ui/main_window.py: _add_body` — если расширение CAD: конвертация в `work/_cad_<id>_<имя>.stl`, затем обычный путь (триангуляция → тело в список). Имя тела — оригинальное имя файла.
- Новых зависимостей нет: gmsh уже используется приложением для объёмной сетки.
- Многодетальные сборки: каждая загруженная модель становится телом в списке (роль назначается пользователем). «Сборка как деталь» в STEP — работа в CAD-системе пользователя; со стороны AeroOpt сборка импортируется как единая триангуляция.
